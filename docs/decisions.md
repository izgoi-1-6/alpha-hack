# Demo decisions — 2026-10-24

Authority: [canonical contract](superpowers/specs/2026-10-24-credit-route-design.md), `demo-spec-v1`. These are bounded MVP choices, not verified bank policy.

| Ruling | Reason and consequence |
|---|---|
| FastAPI + React/TypeScript/Vite + PostgreSQL; no Spring implementation | User-selected stack; obsolete README placeholders replaced. |
| Exactly three application products; archive all nine research entries separately | A full catalog is retained without pretending unsupported products have executable rules. Demo JSON alone drives calculations. |
| Unsecured term 300k–3m, 6–36m, 23.50%; revolving 300k–3m, 6–18m, 24%; secured 500k–6m, 12–60m, 21.50% | Explicit demonstration rates/ceilings. Historical 100k single product and research catalog ceilings do not govern new applications. Revolving has no renewal; interest at full utilization, principal at maturity. |
| Low-risk capacity min(product ceiling,3R); medium min(product ceiling,1m,R); secured additionally 70% declared/verified collateral | Prevents catalog maxima being sold as personal capacity. Unknown turnover/collateral yields null, never a promise. Secured limit is declared until document review. |
| Purpose, pattern and amount suitability precede indicative price; avoid collateral when unnecessary | A cheaper secured rate must not outrank an adequate unsecured product merely on price. Deterministic ties use product ID. |
| No score/BKI before explicit submitted consent | Recommendations use turnover upper bound, never a claimed likelihood of approval. Founder majority is not guarantor consent; simplified demo omits sureties rather than fake their verification. |
| Original factors and R1–R12 retained; OFFERED becomes PREAPPROVED | Preliminary approval requires documents/officer final decision. Low-risk smaller amount R9 retained. Product-specific R1/R7 replace historical minimum/term checks. |
| Missing declared data recoverable, unavailable source WAIT_EXTERNAL, finance anomalies manual | Retry uses controlled fixture recovery, not real services. Client-answerable NEED_INFO retains application/assignee and returns MANUAL_REVIEW. Missing consent blocks submit with 422 without BKI. |
| Six guided stages, synthetic representative confirmation instead of passport/OTP/signature | Preserves usable analyst journey without collecting real PII or implying legally effective signing. |
| Opaque 12-hour server sessions; body integer revision; command Idempotency-Key | One simple concurrency/auth contract, no parallel ETag convention or browser token storage. Row locks and partial active uniqueness guard races. |
| Preapproval expires after 14 exact days, including documents/rework | Immutable deadline; expired cases cannot get final approval. Final APPROVED is terminal. |
| BANK_STATEMENT + FINANCIAL_REPORT, secured adds ownership + valuation | Small deterministic checklist; accept is a visibly simulated officer review. Valuation acceptance persists verified value on the accepted current document revision; final LTV reads that immutable evidence. Rejection does not require accepted/complete documents. |

Production pricing, banking/legal conditions, real data permissions, calibrated risk and abuse/file security operations remain future work; no implementation task should silently widen the demo to those integrations.

## Task 3 rulings (recommendations)

Reversible implementation choices made while building the preliminary calculator; the canonical contract above still governs.

| Ruling | Reason and consequence |
|---|---|
| An unconfirmed registry blocks `can_apply` and any `fits`, but the indicative limit and payment stay visible | The contract nulls a payment only when it is unknown or incompatible, and says turnover may be known while the registry is unknown. An inactive company is incompatible and gets no payment. |
| A missing payment always carries its reason in `payment_note` | Null alone reads as an error; the note names the gap (inactive company, incompatible parameters, unknown turnover or collateral, estimate below the product minimum). |
| Every economic number is read from the product policy (revenue multiple, collateral LTV, minimum draw, rates) | A policy change in a new catalog version must change estimates without a code edit; snapshots keep the versions they were computed under. |
| Revolving interest uses integer ceiling arithmetic, term-loan annuities use Decimal half up | A rounded monthly rate can push an exact whole-ruble interest total up by one; the annuity has no exact-integer boundary. |
| «Обычный каталог» is the baseline: the same server figures in fixed catalog order, with no rank, status, reasons, alternatives or criteria | The later comparison needs identical data with guidance removed; the display mode is local UI state until Task 7 assigns it per run. |
| The UI archive list hides the three research entries that reuse a supported product id | They share an id with a live demo product but carry different unverified parameters; the API still returns all nine with `can_apply=false`. |
| One snapshot is saved per calculator edit (after a 300 ms debounce) | The contract wants a saved snapshot id for each estimate; there is no pruning or rate limit in the demo. |

## Task 4a rulings (applications backend)

Reversible choices made while building the questionnaire, submission and scoring API; the controller's binding decisions (lazy expiry placement, respond-info in Task 5, allowed actions, debt as a client answer, attempt-indexed BKI recovery, check order) are in the SDD ledger and the canonical contract.

| Ruling | Reason and consequence |
|---|---|
| A known BKI overdue of 30 days or more rejects (R2) even when the history category is missing | R2 precedes R3 in the spec's rule table, and a retry for the missing history could not change a mandatory stop. The fixtures never combine both. |
| A known turnover source value stays authoritative and is the scored value; a client override is kept beside it and routes R5 | "Persisted company/source fields are authoritative": an inflated override cannot raise the scored limit an officer works within. A value the source lacks is scored as declared and routes R5. A missing turnover source still reports its period end, so that prefill is tagged `source`. |
| A known inactive company's submission persists both consents and goes DRAFT→CHECKING→REJECTED | The submission was accepted for processing with valid consents; no BKI request is made. Missing answers do not block it (known inactive overrides missing finance). |
| Drafts can be created for any supported product in an owned snapshot, whatever `can_apply` says | The contract makes `can_apply` a UI gate and has an unconfirmed-registry case reach the R4 check on submission. `allowed_actions` omits `submit` for a known inactive company. |
| Submit checks conflicts before input: version, draft, current policy, duplicate active application, then R1, consents, R3 | A state conflict cannot be fixed by editing answers. Lazy expiry of the other applications runs inside the duplicate check. |
| One command increments the version once; the check result is a system history step | DRAFT→CHECKING (client) and CHECKING→outcome (system, actor null) share one revision, matching "successful changes increment it once". |
| A command that is the first touch after the preapproval deadline returns a committed 409 `APPLICATION_EXPIRED` | A raised error would roll the lazily recorded expiry back; the refusal now persists exactly one EXPIRED row. |
| Trusted-source recovery records the computed rule (for example R8) with outcome MANUAL_REVIEW | The evaluation shows what scoring alone would decide while the forced review is explicit in its outcome and reasons; R2/R6/R7 still reject. |
| `indicative_limit_rub` is recomputed at submission (`scoring.indicative_limit`: the low-risk upper-estimate formula with the secured LTV cap) on the stage-3 scored revenue — the turnover source value when the source knows it, otherwise the client's declared answer, which keeps its `declared` tag in the evaluation evidence | Old estimates must not promise capacity; the draft keeps the snapshot's figure until then. A declared figure is still only an upper estimate: the declaration routes R5 review. (Wording corrected in Task 5a; behaviour unchanged.) |
| Retry-check evaluates under the product policy pinned at submission | Submitted decisions are never silently migrated to a later policy. |
| Open info requests are shown only while the application is in progress | A terminal application has nothing to answer; the rows stay unresolved as audit evidence. |
| The client-answers NEED_INFO of a submitted check is reachable only through an internal check | Submission already blocks missing answers with 422, so the defensive path is exercised by a service-level test, as the acceptance note on missing_turnover asks. |

## Task 5a rulings (officer review backend)

Reversible choices made while building the queue, claims, preliminary decisions and the customer's information response; the controller's binding Task 5 rulings (split, claim semantics, ASSIGNMENT_REQUIRED, preapproval refusals by evaluation values, reject source states, request-info and respond-info rules, queue default and order, staff detail contents, history roles, allowed actions) are in the SDD ledger and the canonical contract.

| Ruling | Reason and consequence |
|---|---|
| Claim checks state, then another assignee, then version; decisions check assignment, then version, then state, then their own guards | The loser of a claim race learns the real conflict (`ALREADY_ASSIGNED`) instead of a version clash; a non-assignee learns to claim first whatever version it holds. A same-officer claim with a stale version is `VERSION_CONFLICT`. |
| `MANDATORY_STOP` is checked before `LIMIT_NOT_COMPUTABLE`, and a company inactive now (not only when evaluated) is a stop | A high-risk case has both a score below 50 and no limit; the stop is the reason that no answer can fix. Persisted company fields are authoritative. |
| An amount outside the bounds is 422 `AMOUNT_OUT_OF_BOUNDS` with `fields.amount_rub` and `details {amount_min_rub, amount_max_rub}` | The UI can show the exact inclusive range; only the code name is new. |
| Staff application adds `assignee {id, display_name}`, staff `allowed_actions`, `latest_evaluation.factors/review_flags` and `preapproval {amount_min_rub, amount_max_rub, blocked_by}` (MANUAL_REVIEW only) | Decision controls need the bounds and the refusal reason from the server's policy, not a client re-implementation. |
| Staff detail adds `info_requests` (every request, with `officer` and `open`) and `history` (with `actor {id, display_name}`) beside the spec's five keys | The officer must read the client's response after its request is resolved, and staff history may name officers; customer routes stay client-only. |
| respond-info must set every requested path and nothing else (`collateral` covers its details); the merged answers are then re-checked for R3 (`NEED_INFO`) | A response cannot leave a requested field unanswered, slip in unrequested changes (422 `ANSWER_NOT_REQUESTED`) or drop a required answer such as a secured product's pledge before the officer decides. Optional fields may be answered with null. R1 is not re-checked: the need fields it reads cannot change (fix round 1). |
| respond-info is one client history step NEED_INFO→MANUAL_REVIEW (`INFO_PROVIDED`, reason text = the response), with no CHECKING row | The re-check makes no source request; the spec's transition is NEED_INFO→MANUAL_REVIEW and the ruling says it always lands there. |
| The re-check records the rule the rules alone would decide (R2/R6/R7 included) with outcome MANUAL_REVIEW, keeps earlier `declared_finance`/`finance_override` flags, reuses the latest complete BKI report tagged `reused_from_evaluation_id`, and with no BKI evidence at all stays R5 without a score | Mirrors the 4a trusted-source labelling; the officer's preapproval is refused by those computed values. `bki_attempts` now reads the highest recorded attempt (equal to the count before), so a reused report never shifts the recovery index. |
| Controller ruling (fix round 1): the stage-2 need — `purpose`, `funding_pattern`, `requested_amount_rub`, `term_months` — cannot be requested by an officer (422 `NEED_FIELDS_LOCKED`, `fields.requested_fields`, `details.fields`); `collateral` and `collateral.*` stay requestable. respond-info also refuses need answers whatever the request's origin (422 `NEED_FIELDS_LOCKED`) | The original request is never rewritten: an officer wanting less preapproves a smaller amount, and a different need is a new application. Refusing system requests too keeps one rule; a system request naming a need field (only the internal, pre-submit-gate check can build one) is then answerable only by cancelling. The preapproval upper bound, `after_response` and the evaluation's scored-answer snapshot all keep the original request; `indicative_limit_rub` stays the submission figure. |
| Reason codes: `INFO_REQUESTED`, `INFO_PROVIDED`, `R12` (preliminary preapprove or reject), `FINAL_REJECTED` (document-phase reject) | R12 is the spec's officer preliminary rule; the final rejection is not R12. |
| Every questionnaire answer path outside the need, including confirmations and pledge details, can be requested by an officer (`info_requests.OFFICER_PATHS`); BKI categories, company snapshot fields and consents never can (they are not answers) | `ANSWER_PATHS` stays the full list: the request schema rejects anything outside it (422 `VALIDATION_ERROR`) and system requests built from a check's missing answers may name any of it; `create_info_request` refuses a need field only when an officer is set. |
| request-info is refused with 409 `INFO_REQUEST_OPEN` while the application has an open InfoRequest (fix round 1) | No 4a path reaches MANUAL_REVIEW with an unresolved request (trusted-source requests resolve or stay outside review); the check makes that invariant explicit, so a second open request can never hide the first. |
| Controller ruling (fix round 1): the queue lists only submitted rows (`submitted_at` set); never-submitted rows appear only under `status=DRAFT`, which lists drafts; a draft cancelled before submission is never listed (its detail stays readable by id) | It never reached the bank for review. The status filter stays exact (`status=DRAFT` returns DRAFT rows only). Filters and the FIFO order (`submitted_at`, id) run in SQL, so lazy expiry locks rows in a deterministic order; a request for EXPIRED also reads the expiring states, so lazy expiry still runs before the final status check. |
| Preapproval notices name the deadline as the UTC calendar date («срок истекает DD.MM.YYYY, точное время указано в заявке») | No raw UTC timestamp; in Russia's time zones the UTC date is never later than the local date, so the date is never optimistic. |
| A partial unique index admits one preapprove, approve and reject decision per application | Backs the row lock and version check at the database, as the active-application index does for submissions. |
| The customer timeline's `userId` prop chain was removed with the switch to `actor_role` | The frontend change is the minimum to keep labels correct after the API stopped sending actor ids; 5b builds the officer UI. |

## Task 6a rulings (documents and final decision backend)

Reversible choices made while building documents, private storage, the officer's document review, final approval and the handoff link; the controller's binding Task 6 rulings (split, parsers, error codes, storage, downloads, upload digest, review rules, below-minimum refusal, summary/actions, handoff path) are in the SDD ledger and the canonical contract.

| Ruling | Reason and consequence |
|---|---|
| Customer document actions are named `upload_document`, `delete_document`, `complete_documents` | The ruling says "upload/delete/complete"; bare `delete`/`complete` would read as deleting the application or completing the questionnaire. The staff names `review_document`/`approve` are as ruled. |
| `document_summary.current_uploaded` counts requirements with a current revision whatever its review; `accepted`/`rejected` count the reviewed ones; the summary is null until `preapproved_at` is set and stays (read-only) on later terminal states | "2 uploaded, 1 accepted, 1 rejected" reads naturally; pending review = current_uploaded − accepted − rejected. A draft or a case rejected in review has no packet to describe. |
| A REJECTED current revision may be deleted as well as an UPLOADED one; the DELETED row keeps its review reason, the bytes go | The spec allows deleting an "unaccepted current file". The A09 audit trail is the replacement path (superseded revisions keep their bytes); a client who deletes a rejected file only loses that copy. Reversible by refusing DELETE for REJECTED. |
| An upload checks ownership (404) before reading any byte, validates the whole file before taking the row locks, and only then runs the shared command sequence (lock with lazy expiry, replay, expired refusal, version, state, checklist) | A stranger cannot make the server read 20 MiB for a resource it may not see, and no lock is held while parsing. The pre-check applies no lazy expiry, so the lock's committed `APPLICATION_EXPIRED` refusal still happens. File errors therefore precede version/state errors. |
| New codes: 422 `DOCUMENT_TYPE_NOT_ALLOWED` (type outside the product checklist), 409 `DOCUMENT_NOT_CURRENT` (deleting a superseded revision), 404 `DOCUMENT_NOT_FOUND` (absent, other application's, or DELETED), 409 `DOCUMENTS_INCOMPLETE` (`details {missing, rejected}`), 409 `DOCUMENT_NOT_REVIEWABLE`, 422 `VERIFIED_VALUE_REQUIRED`/`VERIFIED_VALUE_NOT_ALLOWED`, 409 `DOCUMENTS_NOT_ACCEPTED`, 409 `LIMIT_BELOW_MINIMUM` (unsecured twin of `COLLATERAL_INSUFFICIENT`) | Each refusal is distinguishable for the UI and follows the spec's status map (state of persisted data 409, input 422). `LIMIT_BELOW_MINIMUM` is unreachable with consistent data (preapproval already respects the turnover limit). |
| Stored names: last path segment, NFC, category-C characters removed (controls and bidi overrides), whitespace collapsed, ≤200 characters keeping the extension; percent escapes are kept literally | Names are display data only and never reach the filesystem; downloads add a sanitized ASCII fallback plus RFC 5987 `filename*`. Decoding `%22`-style escapes would make literal percent signs ambiguous. |
| Content rules beyond the ruling: an empty file is 422 only after extension and MIME agree; markup markers anywhere are 415; PNG must end at IEND, JPEG at EOI and PDF with only whitespace after the last `%%EOF` (else 415); PDF active names are searched both in the parsed objects (every xref entry and object stream) and as raw tokens in the bytes outside the data of the stream objects the parser read; an encrypted PDF is 422; images above 40 megapixels are 422 from the header, before decoding, and Pillow's own bomb guard is switched off (`Image.MAX_IMAGE_PIXELS = None`) | Appended archives and HTML are the usual polyglots; the raw scan also catches objects outside the xref table that a repairing viewer might still run. Fix round 1: stream data is skipped by the raw scan, because compressed or binary data matches a token such as `/AA ` by chance (about 0.8% per MiB). Fix round 2: only the data of stream objects pypdf actually read is skipped, located from the `endstream` that closed it, so stream-like text in a comment, a string, a dictionary or outside every object is scanned, and every search is linear in the file size. Residual risk: a hostile object hidden *inside* a real stream's data is data, not an object, unless a repairing viewer misreads that stream's length. The location is exact for up to 32 whitespace bytes before `endstream` and 32 spaces after `stream`. Beyond that the data is taken as its length just before `endstream`: a few more data bytes are scanned (a possible chance false refusal), and nothing outside the data is ever skipped. One pixel budget for all images means the same 422 and no `DecompressionBombWarning` between 89 and 179 MP. A real scan with an XMP `<?xml` packet passes (that marker is not searched); markup markers still apply to the whole file (a chance match in binary data is about 6e-5 per MiB), and a PDF whose visible text contains `<html ` would be refused — acceptable for synthetic demo files. |
| The final limit is recomputed with `scoring.turnover_limit` from the latest evaluation's risk and scored revenue, capped for the secured product by `scoring.collateral_cap` of the accepted valuation's verified value; final ≤ min(preapproved amount, that limit) | One rule for unsecured and secured products ("same LTV/turnover rule"); a verified value above the declaration can never lift the final amount above the preapproval. Staff views expose it as `final_approval {amount_min_rub, amount_max_rub, verified_limit_rub, blocked_by}` (DOCS_UPLOADED only), mirroring `preapproval`. |
| A document review writes no OfficerDecision; accepting is a same-state edit (version +1, no history), the first rejection is the officer step `DOCUMENT_REJECTED` with the officer's reason; completion is the client step `DOCUMENTS_SUBMITTED`; approval `FINAL_APPROVED` | OfficerDecision is the decision on the application (its once-only index covers approve/reject); the review lives on the Document row (reviewer, time, reason), which is the spec's place for it. |
| `GET /applications/{id}/documents` is customer-only; officers read documents through the staff detail (`documents`, every revision with `reviewer`) and may download through the shared download route | Keeps customer routes client-only as in Tasks 4–5 while honouring "owner or officer" for downloads. |
| The checklist adds `notice` (the «Демонстрационная проверка документов» label) and each document a `download_url`; staff detail adds top-level `requestable_fields` | The server owns the label and the paths (6b shows them); the URL is the authorized API route, not a public link. |
| Downloads also send `Content-Security-Policy: default-src 'none'; sandbox`; Starlette's file response keeps its ETag/Last-Modified/Range support | Defence in depth for user-supplied bytes; the response stays `private, no-store`. The API middleware now only defaults `Cache-Control: no-store`, so other responses are unchanged. |
| The web container's nginx accepts bodies up to 21 MiB on `/api/`, and the API container stores files in the named volume `credit_route_documents` | Without it, nginx answers uploads above 1 MiB with its own 413; the volume keeps bytes beside the persisted rows when containers are recreated. Container files only; the verified host baseline is unaffected. |
| The handoff link takes the shared command path (locks, replay, expired refusal) and records only its idempotency row | It is a stateful POST by contract, but it changes nothing: no version, history or notification. |
| A file renamed into place whose transaction then never commits is removed; a crash between the rename and the commit can leave an orphan file, and no startup sweep exists | Every request path is covered by the session hooks; a sweep would be production hardening. Fix round 1: only the outermost commit settles files (a SAVEPOINT release also fires `after_commit`). |
| Fix round 1: an upload ends its read transaction after the ownership check, and its command runs at the time the body has arrived (fix round 2: the clock comes from the `get_clock` dependency and is called then) | A slow 20 MiB upload holds no pooled connection in an open transaction, and an upload that finishes at or after the deadline records the expiry and is refused (409 `APPLICATION_EXPIRED`) instead of committing; `created_at` is the arrival time. Other commands are instantaneous and keep the request-start `Now`. |
| Fix round 1: each multipart part may carry at most 8 headers of at most 4 KiB (name plus value), checked by the intake itself; the parser library's limits are a looser backstop | The limit no longer depends on a library default; header bytes accumulate in a bytearray. Refusals are 422 `VALIDATION_ERROR`. |

| Fix round 2: each stream object in the cross-reference table is read a second time from its offset, with pypdf's own `read_object_header`/`read_object`, to learn where its `endstream` is; the data is then found by stepping back from `endstream` through whitespace, at most 32 bytes, to the first point that follows a `stream` keyword. If none is found, the data is the `size` bytes just before `endstream` | The fix-round-1 regex was quadratic (8.8 s for 160 KB of unterminated openers). Searching forward from an object's offset instead lets a fake keyword in a dictionary string or in the data, or a real keyword with many spaces, define a span reaching past the data. ## Task 6b rulings (document phase UI)

Reversible presentation and interaction choices made while building the customer checklist, the officer's document review, the final decision and the demo hand-off; the controller's 6b rulings and the canonical contract govern.

| Ruling | Reason and consequence |
|---|---|
| Uploads on one page run one at a time: a file chosen during an upload waits «В очереди»; each upload sends the version the previous upload returned, after the page has reloaded | Every stored upload raises the version, so parallel uploads would meet 409 `VERSION_CONFLICT`. A lost response pauses the queue until the customer repeats that upload (same key, the server replays) or dismisses it; a version conflict reloads and keeps the file for «Повторить загрузку» with the new version. |
| The upload's idempotency body identity is requirement + version + file name + size + last-modified time; no browser-side SHA-256 | The server's digest (type, version, SHA-256, name) stays the guard: a different file reaching the server under a reused key is refused with 409 `IDEMPOTENCY_CONFLICT` and shown. Hashing 20 MiB in the page would cost time for no extra safety. |
| The browser pre-check blocks a disallowed extension, an extension the browser's MIME type disagrees with, an empty file and anything above 20 MiB, before sending; everything else is the server's decision, shown as it words it | Convenience only (no 20 MiB upload that is bound to fail). Because the size check matches the server limit, a real 413 cannot come from the UI; its display is tested with one injected reply carrying the documented text. |
| Deleting a current file asks for confirmation on its row; a rejected current file is deletable too | The server allows it (6a ruling); a deletion cannot be undone, but the file can be uploaded again. Earlier revisions stay listed («Прежние версии»), a superseded rejected one labelled «Отклонён · заменён». |
| The checklist sits after the amount tiles on every status from preapproval on and stays as a read-only record with downloads after the document phase | `document_summary` is set from preapproval on (6a); the packet remains audit evidence on approved, rejected, cancelled and expired applications. |
| The deadline is shown with its local date and time, beside «Загрузка и замена документов срок не продлевают» | The server's notification only names the UTC date and points to the application for the exact time. |
| The hand-off page reads the application as its owner instead of calling the link endpoint again; only APPROVED shows the simulation; a wrong owner sees «Страница недоступна» (the server's 404), a non-APPROVED application «Переход пока недоступен», an officer «Нет доступа» with no request | A direct visit works without a command; the link endpoint stays the action behind the button, and only a URL matching `/demo/alfa-business/{id}` is opened. |
| Logging out (or a lost session) resets the path as well as the query | As with query deep links, the next account never lands on the previous one's page; a logged-out visit to the hand-off address goes through the login to the home page. |
| Officer document reviews are serialized across rows; final approval asks for confirmation; the amount follows a changed bound until edited (also for preapproval) | Each review raises the version. The confirmation mirrors the final rejection. An untouched prefill never sends a stale bound. |
| The request-info picker shows the server's `requestable_fields`, grouped by questionnaire stage, pledge details included as the server lists them | Supersedes the 5b ruling that mirrored `OFFICER_PATHS` and offered the pledge only as a whole. Labels are the questionnaire's own (three confirmations corrected); unknown paths are offered under their path. |
| A version conflict says typed data is kept only when the refused decision's form is still offered after the reload | Otherwise it says the decision is no longer available (5b review minor). |
| The officer's document panel is the first card of the evidence column from preapproval on | In the document phase the review precedes the final decision in the right column. |
| Browser-test JPEGs are encoded by the page's canvas; PDFs and PNGs are written byte by byte in the test | The Node runner has no image library; every file is synthetic and generated per run. |
